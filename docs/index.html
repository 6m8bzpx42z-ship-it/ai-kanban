Close a blocker. The board moves itself.

Nobody maintains a “blocked” flag, because nobody can be trusted to. Close the blocker from the terminal — from another window, from an agent running in the background — and the card it was holding moves on its own, within a couple of seconds, with nothing clicked in the browser. 

$ bd close <the-blocker-id> -r "SQLite wired, verified by reading a row back."

Then look at what landed: the card that appeared is badged frees 2 others. It is worth more than the one you just finished. That's leverage, and it's invisible in a flat list.

Why an agent can use it

Three properties, and the first one is why the rest work.

Derived, not stored

Ready and Blocked come from the dependency graph on every load. “What should I do next” stops being a judgement call and becomes a query.

Claim before starting

An agent claims a card before it touches code, so two of them don't quietly start the same job and edit the same files.

Done leaves evidence

Every closed card carries a written reason — what changed and how it was checked. A wall of “done” is worth nothing three weeks later.

Get it running

Four files into an existing Next.js app. No additional npm packages.

  1. Install beads. The board reads it and never keeps its own copy of anything. 
    $ brew install beads
$ cd your-project && bd init
  2. Copy the four files in — the API route, the board page, the component, and the comparator.
  3. Check your @/* alias points at the same root the files landed in, or swap the imports for relative paths.
  4. Open /board. Full setup notes, the gotchas that will bite you, and the tests are in the README.
